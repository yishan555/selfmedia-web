# 写作结构选择

先明确本篇目的，再选结构；不要因为上一篇有效就重复同一骨架。

## 四步选择

1. **内容目的**：本篇要解释原理、观察信号、评估产品、提供教程，还是提出判断？用一句话明确读者得到什么。
2. **证据与论证**：有哪些本题原文、数据与图片？需要叙事、对比、反驳还是分步骤？没有一手操作记录时，不选亲测/现场经验叙事。
3. **结构模式**：必要时读取 `structure-pattern-library.md`，选一个主模式，最多搭配一个补充模式。短图文压缩为清晰信息点；长文保留小标题和论证层级。
4. **开头与结尾**：必要时读取 `hook-ending-library.md`，以真实事实或具体问题开头。结尾应回应开头；行动建议与讨论邀请按需要添加，不统一粘贴“你怎么看”。

## 同会话 Humanizer

写完后检查：是否有空洞套话、机械转折、无证据强保证、假亲测、被夸大的标题？删改这些表达，但保留个人判断、事实限定和来源。

正文规范见 `platform-format.md`。任务包提供的范围、证据、平台和已有返修反馈优先；参考模式是写作方法，不是强制字数或独立调度节点。

结构库中的案例出自历史语料，原始资料已存入 `archive/pre-slim-20261111`。它们不是当前稿件事实依据，不要求安装包访问仓库历史或旧资料目录。
