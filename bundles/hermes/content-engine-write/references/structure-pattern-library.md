# 文章结构模式库

> 历史出处：`archive/pre-slim-20261111`（`f336763`）中的语料与拆解笔记。保留的是结构方法，不是本篇事实证据；不要把历史示例当亲身实测或当前来源。

本库从 49 个高质量中文博客 / 公众号（约 310 篇文章，覆盖科技观察、产品洞察、设计视角、人文随笔等方向）的逐篇结构拆解笔记（历史语料拆解笔记）中归纳而来，供 `content-engine-write` 技能在写作前做"结构诊断"时调用：先判断本次选题最接近哪个模式（或哪两个模式的组合），再套用对应的骨架、节奏和适用边界，而不是从空白开始想结构。

**使用方式**：
- 模式可以单独使用，也可以混合使用（例如 SP-02 的历史类比开头 + SP-14 的"设反方再化解"中段 + SP-26 的呼应式收尾）。
- 每个模式给出的"结构骨架"是思维路径，不是死板的段落数，具体到小红书图文时通常需要压缩到 3-5 个信息卡；到公众号长文时可以保留完整层级。
- "适用选题类型"和"不适用场景"是从真实语料里的效果反推出来的边界，不是猜测，写作前先对照检查，避免选题和结构错配（例如把需要强判断的新品评测套成"观察笔记式"留白，会显得没有观点）。
- 示例文章仅为历史结构出处，原文位于归档 `archive/pre-slim-20261111` 的 `docs/reference articles/`；当前包不依赖该目录，示例不能作为本篇事实证据。

### SP-01 反常识拆台式立论

- **适用选题类型**：产品/公司决策评论、行业现象解读、需要"纠正大众直觉"的判断类选题。
- **不适用场景**：纯新品参数速报（没有判断空间）；情感/人文类随笔（拆台式论证会显得生硬）；证据不足时不要用——这个模式对论证严密度要求高，站不住会显得标题党。
- **结构逻辑与节奏**：先抛出一句会被当成"标题党"的反常识断言，立刻自己质疑这句话，用数据/事实确认现象真实存在，再依次排除大众最容易想到的表面解释，最后指出真正的结构性原因藏在别处。转折词（"但""其实不然"）密度中高，且每次转折都伴随认知升级而非简单否定；长句做论证，关键判断句压成短句独立成段；需要 1-2 句可截图的悖论式金句收尾。
- **文章结构骨架**：
  1. 抛出反常识断言（10%）
  2. 自我质疑/承认这句话"很容易被误解"（10%）
  3. 用数据/事件确认现象真实存在（15%）
  4. 逐一排除表面解释（30%）
  5. 揭示真正的结构性原因（25%）
  6. 悖论式/警示式收尾（10%）
- **示例文章**：`1q43/01-WorkBuddy成功是因为腾讯办公套件太烂了.md`、`jaketao/02-再夯的机器人也学不会手工缝线.md`

### SP-02 历史/行业类比先行式

- **适用选题类型**：技术趋势判断、新范式解读、需要"拉长时间尺度"说服读者的选题（如"AI会不会颠覆XX行业"）。
- **不适用场景**：产品测评类选题（类比会冲淡评测的具体性）；小红书短图文（历史铺垫拖慢首屏，需要压缩到一句话类比）；读者对类比对象不熟悉时（类比失效反而增加理解成本）。
- **结构逻辑与节奏**：开头不直接讲当下主题，先讲一段跨领域、跨年代的历史/行业演化史（游戏史、技术发明史、旧理论），从中抽出一条一般性规律，再把这条规律"嫁接"到当下的科技/产品命题上，用规律去解释、预测当下现象。长句叙事史料，短句做规律提炼；转折词少，靠"这条路，今天……正在重走一遍"式的桥接句完成映射。
- **文章结构骨架**：
  1. 讲一段与主题看似无关的历史/行业演化史（25%）
  2. 从历史中抽出一条一般性规律（15%）
  3. 明确点出"这条规律正在当下重演"（10%）
  4. 用当下案例逐一验证规律（35%）
  5. 给出基于规律的判断或预测（15%）
- **示例文章**：`mikecaptain/01-AI产品形态的范式迁移.md`、`ruanyifeng/03-资源社会公平与算力.md`

### SP-03 一线经验命名对子式

- **适用选题类型**：从业者视角的产品/职业洞察、"AI如何改变XX职业"类选题、需要建立个人权威感的判断文。
- **不适用场景**：作者本人没有一手实操经验的选题（硬编造会显得空洞）；纯资讯速报（不需要抽象概念）；篇幅极短的小红书单图文案（对子式概念需要一定篇幅才能立住）。
- **结构逻辑与节奏**：从作者自己真实的一线操作细节切入（不空谈行业），从案例中抽出一组二元对仗式的概念命名（如"界面思维vs系统思维""process属于Agent，direction属于人类"），用这组对子重新解释一批现象，最后落回身份/行动判断。金句几乎全部采用"A。B。"或"不是A，而是B"的对仗短句，独立成段。
- **文章结构骨架**：
  1. 具体一线操作细节（20%）
  2. 从案例中抽出概念对子并命名（15%）
  3. 用对子重新解释多个相关现象（35%）
  4. 三层意义升维（个人→身份→行业）（20%）
  5. 落回身份认同或行动判断（10%）
- **示例文章**：`caicai/01-AI-Coding对产品设计师意味着什么.md`、`limboy/03-共型人才AI时代个体进化论.md`

### SP-04 挑战者颠覆叙事

- **适用选题类型**：新品/新公司挑战行业巨头的评测、"小团队如何打败大厂"类商业故事、颠覆式创新案例分析。
- **不适用场景**：巨头方或既有产品的正面报道（没有"挑战者"张力）；数据来源不可验证的选题（这个模式依赖具体价格/份额对比，源头不实会露馅）；纯设计/审美类评测（缺乏商业对抗维度）。
- **结构逻辑与节奏**：先建立"巨头/行业惯例"这个对照物（垄断份额、高价、旧范式），再让挑战者用更低价格或更巧的技术切入被巨头忽视的边缘市场，中段用技术拆解坐实差异化优势，结尾升华成"颠覆式创新""降维打击"式的通用商业判断。数据密度高（价格、份额、续航等对比数字），类比常借用历史案例（诺基亚/塞班）强化说服力。
- **文章结构骨架**：
  1. 建立"巨头/行业惯例"对照物，给出其垄断数据（20%）
  2. 挑战者战绩/反常识价格数据前置（15%）
  3. 谁做的：团队/创始人背景（10%）
  4. 技术/策略拆解，说明如何做到（30%）
  5. 历史类比强化（诺基亚、燃油车等）（10%）
  6. 升华为通用商业理论 + 风险平衡（15%）
- **示例文章**：`ai-business/ELEHEAR：深圳一副助听器，登顶亚马逊品类第一.md`、`ai-business/库犸科技 MAMMOTION：单品月销2870万，全球第一.md`

### SP-05 战绩递进钩子式创业报道

- **适用选题类型**：创业公司/新产品的成长故事、融资新闻解读、"小团队做出大成绩"类报道。
- **不适用场景**：负面/失败案例报道（递进式加码天然带乐观基调，与失败叙事冲突）；需要克制、审慎语气的严肃议题；数据无法进一步"加码"的平淡新闻。
- **结构逻辑与节奏**：开头不是一次性甩出最大数据，而是先给一个战绩，紧接着第二句再给一个更具体/更惊人的战绩，制造"还不止这样"的持续钩子。中段用小标题分节做"是什么/为什么/怎么做/普通人能学到什么/风险"的清单体，几乎不用转折词，靠小标题切换承担转折功能。
- **文章结构骨架**：
  1. 战绩1（15%）
  2. 战绩2（比战绩1更具体或更大）（15%）
  3. 团队/创始人背景（15%）
  4. 产品能力清单化展示（20%）
  5. 为什么火/怎么做到（20%）
  6. 风险与槷点平衡 + 金句收尾（15%）
- **示例文章**：`ai-business/Genspark：20人团队，12个月干出2.5亿美元.md`、`ai-business/RingConn：上交教授做一枚戒指，Kickstarter拿441万.md`

### SP-06 人物特稿环形叙事

- **适用选题类型**：创始人/产品负责人的人物故事、"从失败到成功"的创业复盘、需要情感代入的深度报道。
- **不适用场景**：账号本身没有一手采访/私人叙事资源的选题（硬编造对话会失真）；纯观点评论（缺少真实人物弧线支撑）；短图文（人物弧线需要足够篇幅才能立住）。
- **结构逻辑与节奏**：用戏剧性场景（会议现场、深夜决定）倒叙开场，先剧透结果（融资额、荣誉），再倒回人物的成长/失败史，中间靠"关键他人的一句真实原话"触发认知转折（而不是作者自己的分析句），结尾呼应开头场景或原话，形成闭环。转折靠引语而非连接词完成，戏剧性和场景感强。
- **文章结构骨架**：
  1. 戏剧性场景/结果剧透（15%）
  2. 倒叙人物成长史（20%）
  3. 失败/转折链条（每次失败配一句他人原话）（30%）
  4. 产品验证（用数据/案例证明转型成功）（20%）
  5. 呼应开头场景或原话收尾（15%）
- **示例文章**：`ai-business/Meshy胡渊鸣：三次翻车后，把两周的活压到2分钟.md`、`ai-business/YouWare明超平：上线48小时，访问破100万.md`

### SP-07 硬件新品速报体

- **适用选题类型**：新硬件/新产品发布快讯、需要快速交付信息而非深度分析的选题、编辑部日常速报栏目。
- **不适用场景**：需要建立"账号独立判断力"的深度观察文（这个模式判断克制、几乎不下重锤）；已经建立强人设的观点账号（纯速报会显得像"通稿转发器"）；需要情绪钩子驱动传播的选题。
- **结构逻辑与节奏**：事件/独家信源前置 → 产品参数拆解 → 与同类竞品横向对比 → 企业/创始人背景考古 → 可选的克制结语判断（也可以不给结论，直接用融资信息/渠道信息收尾）。编号小标题（01/02/03）强制分节，转折词极少且精准，反问几乎为零，数据密度高。
- **文章结构骨架**：
  1. 事件/独家信源速览（10%）
  2. 产品形态与参数拆解（30%）
  3. 与同类产品对比（20%）
  4. 企业/创始人背景（20%）
  5. 结语判断或信息收尾（不强求升华）（20%）
- **示例文章**：`ai-vision/戴森推出全球首款搭载摄像头的AI电动牙刷.md`、`ai-vision/融了2个亿后，灵宇宙再推出可穿戴机器人：把“AI吊坠”和“桌面机器人”二合一.md`

### SP-08 自我修正螺旋式论证

- **适用选题类型**：需要建立"作者比读者更清醒"信任感的观点文、对复杂判断需要多层限定的技术/商业分析、想要避免"一边倒站队"风险的选题。
- **不适用场景**：需要强烈行动号召的选题（螺旋式自我修正天然削弱确定性）；小红书短图文（篇幅不够展开多轮自我修正，压缩后容易显得啰嗦）；读者对连续让步转折缺乏耐心的快消场景。
- **结构逻辑与节奏**：先给一个初步、直觉性的判断（"十个月回本≈毛利率87%"式的粗略换算），再用"但""严格来说""并不能直接等同于"主动推翻自己刚给出的结论，逼近更精确、更有限定条件的判断，如此重复2-3轮。转折词密度全篇最高，每次转折都对应一次认知升级而非情绪反转。
- **文章结构骨架**：
  1. 给出初步直觉判断（15%）
  2. 自我推翻/加限定条件（15%）
  3. 更精确的第二轮判断（20%）
  4. 再一次自我修正（可重复1-2次）（30%）
  5. 收束到最终留有余地的判断（20%）
- **示例文章**：`airing/01-当AI拿走一切之后.md`、`devtang/01-梁文锋四小时投资人会议有感.md`

### SP-09 观点先行清单式论证

- **适用选题类型**：技术/工程原理科普、需要系统性交付判断的深度长文、"为什么XX事情本质是老概念重走老路"类选题。
- **不适用场景**：需要悬念驱动的传播型内容（这个模式论点提前亮出，悬念感弱）；情感/人文类随笔；证据不够多元时（清单式论证依赖多个独立案例互相加固，只有1个案例会显得单薄）。
- **结构逻辑与节奏**：开头即给出核心反直觉判断，不铺垫悬念；随后模块化展开，每个模块独立成立，用真实案例/对比表/代码示例逐一验证同一个核心判断，模块之间是"平行加固"关系而非层层递进。段落被表格/代码块/图打断，形成呼吸感；金句几乎每节都有一句。
- **文章结构骨架**：
  1. 开篇直接给出2-3条反直觉判断（15%）
  2. 模块1：原理+案例（20%）
  3. 模块2：原理+案例（20%）
  4. 模块3：原理+案例（20%）
  5. 用真实项目/案例把所有模块串成一个可运行系统（15%）
  6. 反模式清单/浓缩总结（10%）
- **示例文章**：`tw93/03-你不知道的Agent.md`、`manateelazycat/04-高质量商业软件构建的秘密.md`

### SP-10 命名框架式

- **适用选题类型**：需要提出"原创概念"建立账号识别度的选题、把零散现象系统化的行业观察、任何希望被广泛引用转发的判断文。
- **不适用场景**：概念本身站不住脚或过于牵强时（生造词会显得为赋新词强说愁）；纯资讯速报（没有篇幅展开定义和验证）；已有公认术语的领域（重新命名反而制造混乱）。
- **结构逻辑与节奏**：把一个现象或一批案例提炼、命名成一个自造或借用的隐喻词（"哈勃半径""UX债务""锯齿智能""执行导向型UI vs 决策裁判型UI"），命名之后，后续所有段落都反复调用这个词本身来推进论证，而不是说一次就丢掉。这个词本身承担了金句和记忆锚点的双重功能。
- **文章结构骨架**：
  1. 铺垫已有的、读者熟悉的相邻概念（20%）
  2. 制造认知缺口，引出新概念并正式命名（15%）
  3. 用命名词重新解释一批现象（35%）
  4. 讨论命名概念的边界/适用范围（15%）
  5. 泛化为普遍判断，命名词收尾（15%）
- **示例文章**：`1q43/04-一个新的AI记忆层概念哈勃半径.md`、`mysecretrainbow/03-AI正在淘汰的10种UI交互模式.md`

### SP-11 多声源引语拼贴重建

- **适用选题类型**：深度调查报道、有多方利益相关者的争议事件、需要"呈现证据而非直接说教"的严肃议题。
- **不适用场景**：账号没有一手采访资源的选题（硬编造引语有伦理和可信度风险）；观点型短文（拼贴体篇幅长、节奏慢，不适合强钩子场景）；需要账号明确表态的选题（这个模式作者角色克制，几乎不下判断）。
- **结构逻辑与节奏**：不先给结论，而是按时间线或人物线穿插不同当事人、专家的直接引语，让证词自然产生张力或互相印证，作者角色是"编排者"而非"说教者"。转折靠场景/引语切换完成，几乎不用"但是"类连接词；结尾常收在一个极小、极具体的个体化细节上，而非宏大总结。
- **文章结构骨架**：
  1. 事件速览，给出关键事实（15%）
  2. 按时间线/人物线穿插不同当事人引语（40%）
  3. 补充行业背景/历史脉络（15%）
  4. 多方反应的张力呈现（不下判断）（15%）
  5. 收束于一个具体个体化细节（15%）
- **示例文章**：`sanlian/10名顶级登山者，倒在被低估的8000米雪山.md`、`guyulab/短剧遭遇AI：追风口的人，开始掉头 谷雨.md`

### SP-12 深层机制揭秘式

- **适用选题类型**："为什么大家都以为的常识是错的"类科普/揭秘选题、大数据/统计陷阱类内容、需要用机制解释而非情绪说服的技术议题。
- **不适用场景**：没有扎实机制解释能力支撑的选题（这个模式的说服力完全依赖"真正原因"讲得透，讲不透会显得虎头蛇尾）；需要强情绪钩子的传播型内容（机制解释天然偏理性、偏慢热）。
- **结构逻辑与节奏**：先呈现一个违反直觉的现象（数据量很大却错得离谱），排除表面归因（"不是这个原因"），再用具体的技术/统计机制揭示真正原因，常常在结尾补一句"原因之所以很快找到，是因为失败已成事实……真正难的是提前预判"式的元反思，把"讲道理"升格为"讲方法论"。
- **文章结构骨架**：
  1. 违反直觉的现象+具体数据（20%）
  2. 排除表面归因（15%）
  3. 揭示真正的技术/统计机制（35%）
  4. 元反思：为什么这类错误总在事后才被发现（15%）
  5. 判断收束或警示式金句（15%）
- **示例文章**：`yinwang/03-超人类机器视觉不存在.md`、`changhai/03-大数据的陷阱.md`

### SP-13 先褒后拆证据揭露式

- **适用选题类型**：产品/技术测评中需要"打假"或"验证宣传是否属实"的选题、方法论清单类内容中主动澄清"哪些技巧其实无效"、行业里流传但未经验证的说法辨析。
- **不适用场景**：账号没有能力做实际验证测试的选题（这个模式的可信度来自"我试过了"）；纯正面推荐类内容（先褒后拆的节奏天然带有质疑色彩，容易显得阴阳怪气若用错场合）。
- **结构逻辑与节奏**：先完整、公允地陈述对方（产品/公司/流行技巧）的自我宣称，再用一句极短的反问或独白撕开它（"嗯？微软？"），最后给出留有余地的中肯评价。也可以显性列出"试了这些没用"板块，主动否定行业里流传的技巧再给出真正有效的方法，这种"先打自己脸"的姿态反而增强可信度。
- **文章结构骨架**：
  1. 完整陈述对方的自我宣称/流行说法（20%）
  2. 一句反问或独白撕开表面（15%）
  3. 具体证据/测试结果（30%）
  4. 给出真正有效的方法或中肯评价（20%）
  5. 留有余地的收尾（15%）
- **示例文章**：`tw93/05-你不知道的GEO.md`、`geedea/06-带着鸭鸭和狗狗逃离搜索引擎问题.md`

### SP-14 主动设反方化解式

- **适用选题类型**：容易引发"你没考虑到XX"质疑的强观点文、需要提前化解读者疑虑的判断类选题、复杂议题需要展示论证严密度的深度分析。
- **不适用场景**：篇幅极短的场景（设反方需要足够篇幅才能真正化解，压缩后容易显得为了凑字数硬加一段）；反方观点本身很弱、不值得认真反驳的选题（会显得作者在自问自答走过场）。
- **结构逻辑与节奏**：先给出核心判断，主动设立一个"值得认真对待"的反方观点（"这个反驳值得认真对待，但它没有击穿问题"），再用"概念手术"的方式化解——把一个模糊概念拆分成两个更精确的概念，用精确化代替简单否定来化解反方。这种"重新拆分概念"式的论证比举反例更有记忆点。
- **文章结构骨架**：
  1. 给出核心判断（15%）
  2. 铺陈支撑证据（25%）
  3. 主动提出最强反方观点（15%）
  4. 用概念拆分/精细化化解反方（25%）
  5. 强化后的最终判断，留一定弹性空间（20%）
- **示例文章**：`1q43/06-AI不会带来超级组织.md`、`yage/03-OpenClaw是什么.md`

### SP-15 认知反转叙事

- **适用选题类型**：产品/工具的深度体验反转报道（"我以前觉得不行，现在测了一遍"）、个人对某议题态度转变的记录、需要展示"诚实认知升级过程"而非单向宣讲的选题。
- **不适用场景**：需要一致性人设的账号如果频繁"打自己脸"会削弱信任（偶尔使用效果好，高频使用会显得立场不稳）；纯速报类选题（没有"态度转变"的叙事空间）。
- **结构逻辑与节奏**：直接推翻自己过去的判断开篇（"我之前觉得是玩具，现在发现能用了"），建立分类框架/测试标准，用真实测评逐一验证新判断，中间常有"我最初做法是……但实际上……"的认知升级片段，结尾呼应自身写作历史（引用旧文链接）增强"诚实记录成长"的可信度。
- **文章结构骨架**：
  1. 推翻自己过去的判断（15%）
  2. 建立评价框架/坐标系（15%）
  3. 逐项真实测评验证新判断（40%）
  4. 具体实操案例强化（15%）
  5. 呼应自身写作历史，留有开放余地（15%）
- **示例文章**：`victor42/03-AIAgent已经今非昔比了.md`、`caicai/02-AI时代设计师如何提速.md`

### SP-16 观察笔记留白式

- **适用选题类型**：产业观察类非虚构写作、需要"让事实自己说话"而非说教的敏感或复杂议题、账号想要展示克制和专业感而非情绪化判断的场景。
- **不适用场景**：新品评测/趋势判断类选题（读者期待明确结论，过度留白会显得"没有观点"）；小红书图文需要强判断钩子的场景（纯观察笔记打开率和转化率通常偏低）；账号处于冷启动阶段、需要靠单篇树立专业权威的时期（留白依赖已有的信任基础）。
- **结构逻辑与节奏**：把最有冲击力的原始细节和事实按产业链/时间线逐一摊开陈述，几乎不使用转折词，作者几乎不下道德判断或明确结论，把两条线索（如"某产品和已倒闭的先例相似度极高"+"尚无杀手级功能"）并列摆出却不说破，留给读者自己完成推理。
- **文章结构骨架**：
  1. 用拟人化/具体化手法给对象立住形象（15%）
  2. 按产业链/流程顺序逐一呈现细节（40%）
  3. 穿插具体数字和真实人物证词（25%）
  4. 并列摆出隐含矛盾的两条线索，不点破（10%）
  5. 留白式收尾，不给判断（10%）
- **示例文章**：`guyulab/可怜的性爱娃娃85号 谷雨.md`、`ai-vision/融了2个亿后，灵宇宙再推出可穿戴机器人：把“AI吊坠”和“桌面机器人”二合一.md`

### SP-17 设问驱动结构

- **适用选题类型**：科普解释类内容、需要模拟读者疑问链条引导阅读的教学型文章、把复杂概念拆解给非专业读者的选题。
- **不适用场景**：需要强烈个人风格/情绪冲击的选题（连续设问偏理性、偏教学腔）；篇幅极短的场景（设问链需要一定篇幅铺开才能形成完整的"问题→解答"闭环）。
- **结构逻辑与节奏**：把读者可能产生的疑问直接写成显性的过渡句/小标题（"这姿势到底是谁教它的？""AI为什么会胡编？"），再逐一作答，文章骨架由"读者视角的问题链"搭建而非由悬而不答的悬念吊住读者。每问一答之间常配一个类比或具体案例降低理解门槛。
- **文章结构骨架**：
  1. 现象/热梗引入（15%）
  2. 显性设问1 + 类比/案例解答（25%）
  3. 显性设问2 + 类比/案例解答（25%）
  4. 显性设问3（可选）+ 权威验证（20%）
  5. 拔高至行业意义的判断收束（15%）
- **示例文章**：`guokr/机器人“捂脸跑”夺冠，人类要是也这么跑…….md`、`victor42/02-AI元认知你真了解它吗.md`

### SP-18 编年考古推演式

- **适用选题类型**：产品/技术的历史演化梳理、"从过去规律推测未来走向"的预测型文章、需要建立"我比你想得更深一层"权威感的深度长文。
- **不适用场景**：时效性要求极高的速报（考古梳理需要篇幅，来不及讲历史就该出稿的场合不适用）；小红书短图文（历史线索需要压缩到极简才能用，否则第一屏留不住读者）。
- **结构逻辑与节奏**：先埋入一条具体的"侦探线索"（如Beta版本里意外发现的参数），按时间顺序梳理历史演化，每个历史节点都提炼一条规律，最后用累积的规律去反推、验证开头埋下的线索指向的结论，制造"我带你破案"的参与感。
- **文章结构骨架**：
  1. 埋入具体线索/悬念（10%）
  2. 编年体梳理历史演化，每阶段提炼一条规律（50%）
  3. 显式给出"是否可以展望未来"的过渡设问（10%）
  4. 用积累的规律反推/验证开头线索（20%）
  5. 总结规律清单，呼应开头收尾（10%）
- **示例文章**：`steppark/01-从第一代iPhone细数到iPhone12屏幕尺寸进化背后的app设计哲学.md`、`hiwannz/01-从AI编年史到继续发呆.md`

### SP-19 细节切入放大式

- **适用选题类型**：设计/产品体验类观察（从一个具体感官细节引出设计哲学）、"以小见大"的产品洞察、需要制造"悬念延迟点题"效果的软性开头。
- **不适用场景**：需要立即给出明确判断的场景（细节切入天然是慢热的，紧迫的新闻性选题不适合）；账号定位需要"数据说话"而非"感官共鸣"的严肃分析场景。
- **结构逻辑与节奏**：开头不直接说主题词，先用一个具体到几乎人人都有共鸣的感官体验或细节（"有没有过这种感觉"）制造悬念，延迟揭示这个细节对应的抽象设计变量，再逐层放大到整个产品哲学甚至行业本质问题。中段常用设问句独立成段当"软标题"，每个小节都是"直觉误区→反例→原理→匹配原则"的完整闭环，末尾用"好的设计是用户意识不到的设计"式母题收尾。
- **文章结构骨架**：
  1. 感官共鸣式细节铺陈，不点题（15%）
  2. 单句点题，揭示对应的抽象变量（10%）
  3. 逐个子问题拆解（每个都是直觉→反例→原理的闭环）（45%）
  4. 打破"越大/越小/越贵越好"式的参数化二元对立（15%）
  5. 哲学化收尾，回归母题（15%）
- **示例文章**：`design-buff/为什么有些产品圆角，看着就是舒服呢？.md`、`thyuu/01-从一个行业看AI影响.md`

### SP-20 双主体横向对比判断式

- **适用选题类型**：两个公司/产品/路线的正面比较（"A比B激进多少""哪个更值得买"）、行业格局分析、需要给出相对判断而非绝对判断的选题。
- **不适用场景**：单一产品的深度评测（没有明确对照物时这个模式无法展开）；两个对比对象差异过小或过大导致对比没有信息增量的场景。
- **结构逻辑与节奏**：把两个对象（公司/产品/路线）并置分析，用具体数据逐项对比（品牌策略、风险集中度、资产性质等维度），归纳出本质性差异（"前者偏防守，后者偏进攻"），最后上升到趋势判断或全球坐标定位。转折靠对比句式本身完成（"A的风险更集中，B的风险更分散"），不依赖"但是"。
- **文章结构骨架**：
  1. 双主体同时引入，给出各自的核心数据（20%）
  2. 逐维度对比（策略/风险/资产性质等）（40%）
  3. 隐喻命名关键差异机制（15%）
  4. 全球/行业坐标定位类比（15%）
  5. 趋势判断收尾（10%）
- **示例文章**：`weiwuhui/05-阿里赌AI.md`、`stephenleng/03-iPhone为何是普通用户最佳选择.md`

### SP-21 教程式痛点解决体

- **适用选题类型**：工作流/方法论分享、产品使用技巧类内容、"如何用AI做XX"的实操型选题。
- **不适用场景**：纯观点/判断类选题（教程体缺乏观点密度，硬套会显得像说明书）；需要制造悬念或情绪钩子的传播型内容（教程体天然平铺直叙）。
- **结构逻辑与节奏**：从具体痛点或使用场景引入，按操作步骤顺序推进，每一步都给出真实的提示词/代码/操作截图作为证据，并在步骤末尾提炼一条可迁移的原则句，收尾呼应标题重新定义整个方法论（"不要把它当成一台写稿机器，而应该视为一套工作流"）。转折词少，靠"问题→AI解决方案"的因果推进。
- **文章结构骨架**：
  1. 具体痛点/使用场景引入（15%）
  2. 步骤1：给出真实操作证据 + 原则提炼（20%）
  3. 步骤2：同上（20%）
  4. 步骤3：同上（20%）
  5. 效果验证/结果展示（10%）
  6. 呼应标题重新定义收尾（15%）
- **示例文章**：`weiwuhui/06-豆包写稿工作流.md`、`tw93/06-你不知道的AICoding.md`

### SP-22 多产品矩阵横评式

- **适用选题类型**：同类产品/模型的横向测评、"哪个更好用"类选题、需要建立评测标准再逐一打分的内容。
- **不适用场景**：只涉及单一产品的深度体验报告（没有对照矩阵可用）；测评样本不足两个的场景；需要情感/叙事驱动而非理性对比驱动的选题。
- **结构逻辑与节奏**：先给出一个明确的评价框架或几道统一"测试题"，再让多个产品依次通过同一套测试，逐项给出判断句（可以带调侃语气），最后归纳出"哪个象限成熟/不成熟"的规律，并延伸到实际生活场景验证。测评段落句子短促、近似弹幕式点评，是全篇信息密度最高、最"碎"的部分。
- **文章结构骨架**：
  1. 建立评价框架/测试标准（15%）
  2. 产品A逐项测试+判断（20%）
  3. 产品B逐项测试+判断（20%）
  4. 产品C逐项测试+判断（可选）（15%）
  5. 归纳规律（哪类任务哪个象限成熟）（15%）
  6. 实操场景延伸验证 + 展望（15%）
- **示例文章**：`guokr/新任 CEO 首秀，苹果折叠屏最贵卖两万六.md`、`khazix/实测GPT-6 Astra：曾经的那个OpenAI，回来了。.md`

### SP-23 多方观点克制呈现式

- **适用选题类型**：有争议、无标准答案的行业/学术/伦理事件、圆桌对话整理、需要展示多元立场而非单一判断的深度报道。
- **不适用场景**：需要账号明确表态建立人设的场景（这个模式故意"没有统一结论"）；小红书图文（多方观点需要较长篇幅才能立住，短图文容易变成信息碎片）。
- **结构逻辑与节奏**：让多个受访者/立场的观点自然呈现分歧而非被编辑强行统一，小标题本身承担论点提炼功能而非中性分类，转折靠"观点碰撞"完成（"A认为……恰好相反，B认为……"），结尾用多人一句话建议轮播或开放式反问收束，不给单一答案。
- **文章结构骨架**：
  1. 议题引入，预告"观点并不完全相同"（15%）
  2. 分主题小节，每节内呈现2-3方观点分歧（50%）
  3. 观点碰撞处的关键转折（用对照呈现而非编辑评判）（20%）
  4. 多人一句话建议轮播或开放式反问收尾（15%）
- **示例文章**：`qbitai/陶哲轩邓煜究竟在反对什么：AI暴力解题摧毁人类数学精神.md`、`founder-park/AI 硬件创业第一步，先做 AI 还是先做硬件？.md`

### SP-24 悬念钩子延迟兑现式

- **适用选题类型**：需要强开头钩子驱动完读的选题、带一手实验/调查性质的内容、希望制造"追更感"的深度长文。
- **不适用场景**：读者对"被吊胃口"容忍度低的场景（钩子如果拖得太久、兑现太弱会引发反感）；纯速报/教程类选题（不需要悬念）。
- **结构逻辑与节奏**：开头就明示"后面还有更精彩的""这个问题先按下不表，文章最后再回来"，用显性预告制造阅读契约感，中段推进主线论证，结尾兑现开头埋下的悬念（可以是反转、澄清、或补充说明），形成强闭环。
- **文章结构骨架**：
  1. 埋入显性钩子/悬念，明确预告"后面会揭晓"（10%）
  2. 主线内容推进（不涉及悬念本身）（60%）
  3. 回收钩子，给出兑现（20%）
  4. 简短收束（10%）
- **示例文章**：`onojyun/03-人工智能真的能代替写作吗.md`、`guokr/OpenAI智能体一周末攻克千禧难题，纽约大学教授质问：你是不是看过我的草稿？.md`

---

### SP-25 个人项目探针式

- **适用选题类型**：用自己动手做的小项目/小工具去解释行业大命题的选题、具身智能/AI Agent等硬核技术话题的软化处理、"我做了一个东西，从中我发现了……"类内容。
- **不适用场景**：账号本身没有实操能力或项目经历的选题（硬编造"我做了"会失去可信度）；纯观点评论无需实证支撑的场景。
- **结构逻辑与节奏**：先讲清楚自己动手做的一个具体、小型、可复现的项目（含真实挫折细节），再用"这个玩具系统做不到什么"反复作为过渡句，把每一个能力缺口自然引向下一个更大的行业概念，最后用"我的小项目局限之处正是行业难点的缩影"完成从个案到行业的映射。
- **文章结构骨架**：
  1. 个人项目缘起（含具体挫折细节）（15%）
  2. 项目实现细节（20%）
  3. "这套系统做不到什么"作为过渡，引出行业难点1（20%）
  4. 同上，引出行业难点2、3（30%）
  5. 给读者一条可复现的学习路径（15%）
- **示例文章**：`tw93/01-你不知道的具身智能从小机器狗到Optimus.md`、`victor42/06-UI画布尺寸计算器.md`

---

### SP-26 呼应闭环式

- **适用选题类型**：任何需要强记忆点收尾的选题、思辨类随笔、希望读者读完有"问题被正式解答"满足感的内容。
- **不适用场景**：内容本身没有明确的开头意象/设问可供呼应的松散选题（硬凑呼应会显得刻意）；需要开放式讨论、故意不给答案的选题（与呼应闭环追求"闭环感"的目标相悖）。
- **结构逻辑与节奏**：开头设一个具体意象、设问句或他人引语，正文论证展开后，在结尾把开头的意象/设问句原样或变体重新召回，给出一个极简答案或对仗式的收束句，形成强闭环。有时会用"引用后紧接原样复述"的排版技巧强化记忆——先用引用块给出关键句，紧接着不加引号把同一段话再写一遍。
- **文章结构骨架**：
  1. 开头设具体意象/设问/引语（15%）
  2. 正文论证展开（60%）
  3. 重新召回开头的意象/设问（15%）
  4. 极简答案或对仗式收束句（10%）
- **示例文章**：`airing/03-AI没有体验世界的能力.md`、`wangpei/02-费曼识鸟.md`

---

### SP-27 空间/产品导览体

- **适用选题类型**：探店/空间体验类图文、以图片为主导的产品展示、需要"轻文字重视觉"呈现的小红书图文场景。
- **不适用场景**：需要展示专业判断力和观点密度的科技/产品洞察类内容（这个模式观点密度低，几乎不做说理）；公众号深度长文（信息密度设计上是刻意稀薄化的，撑不起长文篇幅）。
- **结构逻辑与节奏**：新闻事件/规格陈述先行 → 官方文案借用转述 → 按真实空间/使用动线分区导览，每区用一句话点题再接大量图片铺陈 → 结尾个人化背书增加可信度 → 实用信息收尾。文字负责"点题+定位"，图片负责"呈现细节"，几乎不用转折词。
- **文章结构骨架**：
  1. 事件/规格陈述（含一个具体反常识数字作钩子）（15%）
  2. 官方文案借用转述（10%）
  3. 分区导览（一句定调+多图铺陈，重复3-5次）（55%）
  4. 个人化背书（15%）
  5. 实用信息/行动邀请收尾（5%）
- **示例文章**：`spain-design/12吨西班牙废旧皮革，构筑Polène沉浸美学空间.md`、`industrial-design/重新设计——“电饭煲”.md`
